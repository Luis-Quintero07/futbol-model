  ---
  📊 FASE 1: Modelo Base Poisson + Dixon-Coles (Semanas 3-5)

  Concepto clave: No intentes "predecir el ganador". Modela distribución de 
  goles → deriva probabilidades 1X2, BTTS, O/U → busca value (tu prob > 1/odds).

  Pasos:
  1. Poisson simple: λ_home = avg_goles_local * fortaleza_local *
  debilidad_visitante
  2. Dixon-Coles: corrige baja probabilidad de empates 0-0, 1-1 (paper 1997, 50
  líneas de código)
  3. Time-weighting: partidos recientes pesan más (exponential decay, half-life
  ~ 150 días)
  4. Backtest walk-forward: entrena hasta 2022, testea 2023, reentrena, testea
  2024...

  Métrica de éxito: ROI % en apuestas con EV+ > 5% (no accuracy). Si no batés el
   closing line consistentemente → el modelo no tiene alpha.

  ---
  ⚠️ Trampas Comunes (evítalas desde día 1)

  1. Look-ahead bias: Nunca uses datos del partido para predecir ese partido
  2. Survivorship bias: Incluye equipos descendidos en histórico
  3. Overfitting: Walk-forward validation obligatorio, no train/test split
  aleatorio
  4. Ignorar vigorish: Tus probabilidades deben sumar > 1 (casa cobra margen)
  5. Sample size: < 500 apuestas = ruido puro. Necesitas 1000+ para saber si
  tienes edge

● 📥 Script de Descarga + Limpieza — Qué hace y para qué sirve

  Qué hace (en 4 pasos)

  # 1. DESCARGA CSVs de football-data.co.uk (gratis, sin API key)
  #    - Temporadas 2018/19 → 2024/25
  #    - Ligas: EPL, LaLiga, Bundesliga, Serie A, Ligue 1, UCL
  #    - Cada fila = 1 partido con ~50 columnas

  # 2. UNIFICA y NORMALIZA
  #    - Columnas consistentes: Date, HomeTeam, AwayTeam, FTHG, FTAG, FTR, 
  #      B365H/B365D/B365A (odds Bet365), B365>2.5/B365<2.5, etc.
  #    - Nombres de equipos estandarizados ("Man United" → "Manchester United")

  # 3. LIMPIA y VALIDA
  #    - Elimina partidos sin odds de cierre (cancelados, pospuestos sin 
  reprogramar)
  #    - Convierte odds a probabilidades implícitas + quita vigorish (margen 
  casa)
  #    - Detecta outliers (odds erróneas, goles imposibles)

  # 4. EXPORTA 2 archivos listos para modelar
  #    - `matches_raw.parquet`   → todo crudo para auditoría
  #    - `matches_clean.parquet` → features base + target (resultado, goles)

  ---
  Para qué se usa (es la base de TODO lo que viene)

  Uso posterior: Poisson / Dixon-Coles
  Qué necesita del dataset: Goles locales/visitante por partido + fuerza de
    equipos
  ────────────────────────────────────────
  Uso posterior: Features xG
  Qué necesita del dataset: Tiros, tiros a puerta, corners (disponibles en
    columnas HS, AS, HST, AST, HC, AC)
  ────────────────────────────────────────
  Uso posterior: Forma reciente
  Qué necesita del dataset: Últimos N partidos de cada equipo (rolling windows)
  ────────────────────────────────────────
  Uso posterior: H2H
  Qué necesita del dataset: Historial directo entre los 2 equipos
  ────────────────────────────────────────
  Uso posterior: Backtest walk-forward
  Qué necesita del dataset: Fecha ordenada cronológicamente (entrena pasado →
    testea futuro)
  ────────────────────────────────────────
  Uso posterior: CLV tracking
  Qué necesita del dataset: Odds de cierre (B365H/D/A ≈ línea de cierre en ligas

    top)

  ---
  Qué NO hace (importante)

  No hace: ❌ xG real (expected goals)
  Por qué: football-data no lo tiene → fase 2 usaremos understat o fbref
    (scraping)
  ────────────────────────────────────────
  No hace: ❌ Lesiones / alineaciones
  Por qué: No hay fuente gratis fiable histórica → fase 2 lo añadimos manual o
    via news API
  ────────────────────────────────────────
  No hace: ❌ Odds en vivo / movimiento
  Por qué: Solo odds de cierre (pre-partido) → para CLV es lo que necesitas
  ────────────────────────────────────────
  No hace: ❌ Datos de árbitros
  Por qué: No incluidos → opcional añadir después
